# Product Workflow — Phase 1-3

本文件在 Phase 0D 产品定位成功后加载，包含并行采集、综合分析和报告输出的完整流程。

---

## 来源规则（全局适用）

### 来源分层

| 层级 | 来源类型 | 用途 |
|------|---------|------|
| **L1** | 官方产品页/规格表、制造商技术文档、官方定价 | 关键参数和价格，必须标注出处 |
| **L2** | 权威评测机构（如 AnandTech/MKBHD/SEMI/拆解报告）、行业分析报告 | 实测数据和深度分析 |
| **L3** | 用户评测、技术博客、论坛讨论 | 使用体验视角，标注"用户反馈" |
| **L4** | 营销文案、软文、未经验证的泄露 | 不得支撑关键事实 |

### 引用规则

- 关键参数**就地标注**来源：`（官方规格）`或`（评测机构名, URL）`
- 禁止段末堆链接
- 分析推断用"分析认为"标记
- 性能对比必须标注测试条件/基准（如"在XX基准下"）
- 价格数据必须标注地区和时间

---

## Phase 1: 并行数据采集（5 个 Subagent）

**关键要求**: 5 个 Agent 必须放在**同一条消息**中发出，确保并行执行。

每个 Agent 使用 `subagent_type: "general-purpose"`。

**全局 Agent 约束**（放在每个 Agent prompt 开头）：

```
## 硬约束
1. 关键参数必须标注来源（官方规格/评测实测），L4 来源不得支撑关键事实
2. 性能对比必须标注测试条件和基准
3. 价格数据标注地区和时间
4. 分析推断用"分析认为"标记，营销话术不可作为事实
5. 字数上限 800 字，优先保留有一手源支撑的内容
```

### Agent 1: 产品骨架与核心规格（What & How）

**description**: "提取{product_name}核心规格"

**prompt**:

```
{全局约束}

你是产品技术分析专家。请提取「{product_name}」的核心规格和关键设计选择。

产品名称：{product_name}
制造商：{manufacturer}
品类：{product_category}
核心规格（初步）：{core_specs}
一手信息：{product_sources}
语言：{lang}

任务：
1. **核心规格提取**：从官方来源提取关键参数（性能/尺寸/重量/功耗/产能等，视品类而定）
2. **关键创新/卖点**：本产品相比前代或竞品的核心差异化（2-3 个）
3. **设计取舍**：产品做了哪些关键 trade-off，每个取舍的得与失
4. **WebSearch 补全**（至少 1 次）：
   - "{product_name} specifications teardown detailed specs"
5. **WebFetch 至少 1 个官方或权威来源验证**
6. **定价信息**：官方定价、各版本/配置价格（标注地区和时间）

输出格式：

**核心规格**：
| 参数 | 数值 | 来源 |
|------|------|------|
| {参数1} | {数值} | 官方规格 / 评测实测 |

**关键创新/卖点**：
1. {创新点}：{一句话说明}（来源）
2. ...

**设计取舍**：
- **{取舍1}**: 得 — {xxx} / 失 — {xxx}（来源）
- ...

**定价**：
- {版本/配置}：{价格}（{地区}, {时间}）（来源）
```

## Phase 2: 综合分析与输出（主线程）

等待 5 个 Agent 全部返回后，执行以下步骤。

### Step 1: 信息整合与校验

逐项检查，任何一项不通过则回溯修正后再继续：

**事实核实 checklist**（逐项过）：
- [ ] **核心参数准确性**：Agent 1 提取的参数是否与官方规格一致？
- [ ] **竞品对比公正性**：Agent 2 的横评是否基于同等测试条件？是否遗漏重要竞品？
- [ ] **价格数据时效性**：所有价格数据是否标注了地区和时间？
- [ ] **代际信息准确性**：Agent 3 的产品谱系是否与官方记录一致？
- [ ] **用户反馈真实性**：Agent 5 引用的口碑是否来自 L2/L3 来源？

**一致性检查**：多个 Agent 对同一结论一致 = 高置信度
**矛盾处理**：不同来源评价不一致 → 在报告中标注争议
**来源审查**：L4 来源支撑的"事实"降级为"待验证"；营销话术不可作为事实
**交叉关联**：
  - Agent 1（规格）+ Agent 2（竞品）→ 产品在竞品中的真实竞争力
  - Agent 3（谱系）+ Agent 4（时机）→ 升级价值和购买时机
  - Agent 5（场景）+ Agent 2（竞品）→ 不同需求下的最优选择

### Step 2: 提炼决策判断

基于全部 Agent 输出，回答三个核心问题：
- **Whether**: 是否值得购买/采购？（明确判断，不骑墙）
- **Why**: 为什么值得/不值得？（一句话核心理由）
- **How**: 如何行动？（立即买/等降价/选竞品，按用户类型区分）

### Step 3: 综合查漏补缺

审视完整报告，检查：
- 是否有重要竞品未覆盖
- 引用链接是否完整
- 各部分之间逻辑是否连贯
- 决策判断是否有充分支撑
- 价格和参数数据是否完整

如发现缺口，使用 WebSearch/WebFetch 补充后再输出。
