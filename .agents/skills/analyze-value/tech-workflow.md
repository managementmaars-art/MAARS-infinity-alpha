# Tech Workflow — Phase 1-3

本文件在 Phase 0C 技术主题定界成功后加载，包含并行采集、综合分析和报告输出的完整流程。

---

## 来源规则（全局适用）

### 来源分层

| 层级 | 来源类型 | 用途 |
|------|---------|------|
| **L1** | 行业权威报告（Gartner/McKinsey/SEMI 等）、标准组织文档、头部玩家官方技术文档、顶级综述论文 | 关键事实，必须标注出处 |
| **L2** | 权威媒体深度报道、专利数据库、学术搜索引擎（Scholar/Semantic Scholar） | 核实与补充 |
| **L3** | 行业分析师文章、技术博客、会议演讲 | 解读视角，标注"外部解读" |
| **L4** | 自媒体、社交媒体、营销内容 | 不得支撑关键事实 |

### 引用规则

- 关键断言**就地标注**来源：`（来源名, URL）`或`（报告名, 发布日期）`
- 禁止段末堆链接
- 分析推断用"分析认为"标记
- 技术指标对比必须标注数据来源和测试条件

---

## Phase 1: 并行数据采集（5 个 Subagent）

**关键要求**: 5 个 Agent 必须放在**同一条消息**中发出，确保并行执行。

每个 Agent 使用 `subagent_type: "general-purpose"`。

**全局 Agent 约束**（放在每个 Agent prompt 开头）：

```
## 硬约束
1. 关键断言必须标注具体来源和出处，优先 L1/L2 来源
2. L4 来源不得支撑关键事实
3. 分析推断用"分析认为"标记
4. 技术指标对比必须标注数据来源和测试条件
5. 字数上限 800 字，优先保留有一手源支撑的内容
```

### Agent 1: 技术骨架与路线图（What & How）

**description**: "提取{tech_title}技术路线图"

**prompt**:

```
{全局约束}

你是技术路线分析专家。请梳理「{tech_title}」的核心技术问题和主要技术路线。

技术名称：{tech_title}
分析粒度：{tech_scope}
核心挑战：{core_problem}
一手信息：{tech_sources}
语言：{lang}

任务：
1. **核心问题**：用几个关键词概括该技术要解决的根本挑战
2. **技术路线图**（3-5 条主要路线）：每条路线的核心思路、关键指标、主要代价
3. **WebSearch 补全**（至少 2 次搜索）：
   - "{tech_title} technology roadmap routes comparison"
   - "{core_problem} 技术路线 对比 survey 2025 2026"
4. **WebFetch 至少 1 个 L1/L2 来源验证**

**技术路线图**（3-5 条主要路线）：

| 路线 | 核心思路（一句话） | 关键指标 | 主要代价（一句话） | 代表工作/产品 | 成熟度 |
|------|------------------|---------|------------------|-------------|--------|
| {路线一} | ... | ... | ... | ... | 成熟/发展中/早期 |

**路线间的关键差异**：
- {路线A} vs {路线B}：{核心 trade-off}（来源）

**关键技术指标一览**：
- {指标1}：当前水平 {xx} → 目标水平 {xx}（来源）
- {指标2}：...
```

## Phase 2: 综合分析与输出（主线程）

等待 5 个 Agent 全部返回后，执行以下步骤。

### Step 1: 信息整合与校验

逐项检查，任何一项不通过则回溯修正后再继续：

**事实核实 checklist**（逐项过）：
- [ ] **技术指标一致性**：多个 Agent 引用的技术指标数据是否一致？不一致则以 L1 来源为准
- [ ] **玩家信息准确性**：Agent 2 中的市场地位/份额是否与权威来源一致？
- [ ] **时间线准确性**：Agent 3 的里程碑时间是否与公开记录吻合？
- [ ] **成熟度判断一致性**：Agent 4 的成熟度判断是否与 Agent 1 的路线图、Agent 3 的发展阶段一致？
- [ ] **应用场景合理性**：Agent 5 的场景判断是否有实际案例支撑？

**一致性检查**：多个 Agent 对同一结论一致 = 高置信度
**矛盾处理**：不同来源评价不一致 → 在报告中标注争议
**来源审查**：L4 来源支撑的"事实"降级为"待验证"
**交叉关联**：
  - Agent 1（路线图）+ Agent 2（玩家格局）→ 各路线的实力对比
  - Agent 3（历史）+ Agent 4（时机）→ 当前处于历史发展的什么位置
  - Agent 5（场景）+ Agent 1（路线图）→ 不同路线的场景适配

### Step 2: 提炼决策判断

基于全部 Agent 输出，回答三个核心问题：
- **Whether**: 是否值得关注？（明确判断，不骑墙）
- **Why**: 为什么值得/不值得？（一句话核心理由）
- **How**: 如何使用这个信息？（具体行动建议，按角色区分）

### Step 3: 综合查漏补缺

审视完整报告，检查：
- 是否有关键路线或重要玩家未覆盖
- 引用链接是否完整
- 各部分之间逻辑是否连贯
- 决策判断是否有充分支撑
- 技术指标是否有数据支撑

如发现缺口，使用 WebSearch/WebFetch 补充后再输出。
