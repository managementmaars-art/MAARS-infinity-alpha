# 官方配置索引页直达策略

## 何时读取

出现以下任一情况时读取本文件：

- 用户在问精确配置项名、阈值、开关、flag、option、parameter、env
- 用户的问题重点是“怎么配”“设置项叫什么”“阈值在哪里设”“哪个参数控制”
- 普通搜索容易把“配置项”误解成“概念说明”或“教程文章”

## 固定决策

1. 先判断这是不是“配置项类问题”。
2. 命中后，先找官方配置索引入口，不先跑通用网页结果浏览。
3. 配置索引入口不限定为 `settings`，也可能叫：
   - `configuration`
   - `config reference`
   - `options`
   - `flags`
   - `parameters`
   - `reference`
   - `system variables`
   - 官方 repo 的配置文件或配置样例，例如 `*.conf`、`*.properties`、`*.yaml`
4. 在官方配置索引入口里，优先找：
   - 精确设置项名
   - 前置开关
   - 默认值或单位
   - 作用范围
5. 只有当官方配置索引入口不足以回答时，才回退到常规 `Context7 -> Exa -> 正文抓取` 链路。

## 执行方式

### 第一步：识别问题是否命中

优先命中以下表达：

- `设置`
- `配置项`
- `参数`
- `阈值`
- `开关`
- `flag`
- `option`
- `parameter`
- `env`
- `timeout`
- `limit`

如果用户真正想问的是“原理”“最佳实践”“设计原因”，不要误用本策略。

### 第二步：优先定位官方配置索引入口

优先顺序：

1. 已知官方文档结构时，直接打开配置索引页
2. 未知结构时，用 Context7 或 Exa 找官方配置索引入口
3. 如果官方文档入口分散、搜索页不稳定，允许改走官方 repo 的配置文件或配置样例
4. 锁定入口后，再在该入口里做精确检索

不要先读博客、问答站或第三方教程来猜配置项名。

### 第三步：抽取答案最小闭环

至少补齐以下信息后再回答：

- 精确配置项名
- 是否有前置开关
- 单位或取值类型
- 去哪里验证生效

如果官方文档只给出了配置项名，没有给默认值或单位，可以明确说明“官方页面未直接写明”。

### 第四步：必要时再扩展搜索

只有出现以下情况时才扩展：

- 官方配置索引页没有该项
- 该项存在，但语义不清
- 需要补示例 SQL、CLI 或配置片段

这时再回到常规搜索链路，不反过来。

## 最小回答模板

- 配置项名：`...`
- 前置开关：`...` 或 “无”
- 单位/类型：`...`
- 验证方式：`...`
- 来源：官方配置索引页 / 官方 repo 配置文件 + 相关官方说明页

## 示例

### ClickHouse 慢日志阈值

- 配置项名：`log_queries_min_query_duration_ms`
- 前置开关：`log_queries = 1`
- 补充项：`log_queries_min_type = 'QUERY_FINISH'`
- 验证位置：`system.query_log`

这个例子里，优先入口是官方 `settings` 页面，因此命中本策略；但策略本身不是只给 ClickHouse 或只给 `settings` 页使用。

## 常见错误

- 把“配置项类问题”直接扔回通用网页搜索，导致多跳检索
- 把 `settings` 当成唯一命名，漏掉 `configuration`、`flags`、`options`
- 官方文档入口已经不集中，却还拒绝使用官方 repo 配置文件
- 先看第三方博客，再回头核对官方文档
- 找到配置项名后，没有补前置开关或验证方式
