# 输出格式规范

## 何时读取

执行搜索并整合结果后，必须按本规范格式化最终回答。

## 强制输出模板

最终回答必须使用中文，并严格使用以下 Markdown 结构：

```markdown
# 主题标题

## 摘要
- 2 到 4 条核心结论

## 详细结果
### 官方文档
- 来自 Context7 或官方文档的关键信息

### 网络资源
- 来自 Exa 或网页读取的网页、博客、讨论或新闻

### 网页读取
- 仅在需要说明正文抓取、清洗方式或降级链路时保留

### GitHub 仓库
- 来自 DeepWiki 的仓库文档概览和深读
- 来自 github-fetcher 的仓库文件内容和目录结构

## 综合结论
- 汇总判断
- 给出适用建议

## 来源
- [来源名称](https://example.com) - 说明该来源提供的信息和来源类型
```

## 章节规则

- `# 主题标题`、`## 摘要`、`## 详细结果`、`## 综合结论`、`## 来源` 必须存在
- `## 详细结果` 下的三级标题按需保留，没有对应来源类型时可以省略，但不能省略 `## 详细结果`
- `## 摘要` 必须使用 Markdown 列表，不允许写成长段落
- `## 来源` 必须逐条列出来源名称、链接、来源类型和用途说明，不能只堆裸链接

## 来源标注规则

- 官方文档类结果明确标注 `Context7`
- 网络搜索类结果明确标注 `Exa`
- 网页正文读取结果明确标注 `网页读取`
- GitHub 仓库文档结果明确标注 `DeepWiki`
- GitHub 仓库文件/目录结果明确标注 `github-fetcher`
- 如果正文读取工具发生降级或切换，必须在正文写明最终采用的读取方式
- 如果读取失败、信息不足或只能返回入口链接，必须直接说明，不能包装成已读取成功

## 语法规则

- 列表必须使用标准 Markdown 列表语法：`-` 或 `1.`
- 链接必须使用 Markdown 链接语法：`[标题](URL)`
- 命令、路径、参数名、库名、字段名必须使用行内代码标记
- 代码、JSON、命令示例必须使用 fenced code block，并尽量标注语言
- 引用外部原文时必须使用 Markdown 引用块 `>`

## 禁止项

- 禁止输出纯文本堆叠结果，不加标题和列表
- 禁止使用 emoji 标题替代标准 Markdown 标题
- 禁止在正文直接裸贴 URL
- 禁止输出未闭合的代码块
- 禁止省略 `## 来源`
- 禁止编造未读取到的网页正文、仓库内容或文档细节

## 回复前自检

1. 标题层级合法，且包含 `## 来源`
2. 列表使用标准 Markdown 语法
3. 每条来源都包含链接、来源类型和用途说明
4. 发生降级、失败或信息不足时，正文已经显式说明
5. 正文没有脱离 Markdown 结构的纯文本堆叠

## 配置项查询的输出补充

配置项查询在 `## 详细结果` 下增加 `### 配置项` 子节：

```markdown
## 详细结果

### 配置项
- 配置项名：`...`
- 前置开关：`...` 或 "无"
- 单位/类型：`...`
- 验证方式：`...`
```
