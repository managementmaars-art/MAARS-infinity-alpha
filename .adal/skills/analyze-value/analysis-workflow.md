# Analysis Workflow — Phase 1-3

本文件在 Phase 0 定位论文成功后加载，包含并行采集、综合分析和报告输出的完整流程。

---

## 来源规则（全局适用）

### 论文原文优先

论文原文是核心事实源。关键技术描述、实验数据必须能在论文中定位。外部搜索用于**核实和补全**。

### 来源分层

| 层级 | 来源类型 | 用途 |
|------|---------|------|
| **L1** | 论文原文、会议官方页、作者主页 | 关键事实，标注 Section/Figure/Table |
| **L2** | Google Scholar、Semantic Scholar、DBLP、OpenReview | 引用量、评审意见 |
| **L3** | 技术博客、学术社区讨论 | 补充解读，标注"外部解读" |
| **L4** | 新闻稿、聚合站 | 不得支撑关键事实 |

### 引用规则

- 关键断言**就地标注**来源：`（论文 Section X.Y, Table Z）`或`（来源名, URL）`
- 禁止段末堆链接
- 分析推断用"分析认为"标记

---

## Phase 1: 并行数据采集（5 个 Subagent）

**关键要求**: 5 个 Agent 必须放在**同一条消息**中发出，确保并行执行。

每个 Agent 使用 `subagent_type: "general-purpose"`。

**全局 Agent 约束**（放在每个 Agent prompt 开头）：

```
## 硬约束
1. 论文原文是核心事实源，关键断言必须标注论文 Section/Figure/Table
2. 外部搜索用于核实和补全，不替代论文原文
3. L4 来源不得支撑关键事实
4. 分析推断用"分析认为"标记
5. 字数上限 800 字，优先保留有一手源支撑的内容
```

### Agent 1: 论文原文骨架提取

**description**: "提取{paper_title}核心骨架"

**prompt**:

```
{全局约束}

你是技术分析专家。请从论文原文中提取核心骨架。

论文：《{paper_title}》（{authors}, {year}）
摘要：{abstract}
原文：{paper_content}
语言：{lang}

任务：
1. **核心问题**：用几个关键词概括本文要解决的核心问题
2. **技术骨架**：提取论文的技术方案骨架，压缩为 3-5 个要点，每点一句话描述，标注论文 Section
3. **关键设计选择**：本文做了哪些关键的技术选择（trade-off），每个选择的优势和代价
4. **关键结果**：最重要的 2-3 个实验结果数字，标注 Table/Figure
5. **作者自述局限**：从 Discussion/Limitations/Conclusion 提取

输出格式：
**核心问题**: {几个关键词}
**技术骨架**:
1. {要点}（论文 Section X）
2. ...
**关键设计选择**:
- {选择}: 优势 {xxx} / 代价 {xxx}（论文 Section X）
**关键结果**:
- {数字}（论文 Table/Figure X）
**自述局限**:
- {内容}（论文 Section X）
```

### Agent 2: 行业路线图与竞争格局

**description**: "调研{core_problem}行业路线图"

**prompt**:

```
{全局约束}

你是行业技术分析专家。请调研论文《{paper_title}》所针对的核心问题「{core_problem}」在行业中的解决方案路线图。

摘要：{abstract}
原文（Related Work / Introduction 部分重点关注）：{paper_content}
语言：{lang}

任务：
1. **从论文 Related Work / Introduction 提取**：论文自身描述的竞争路线和前人工作
2. **WebSearch 补全行业视角**（至少 2 次搜索）：
   - "{core_problem} 技术路线 对比 survey"
   - "{core_problem} approaches comparison 2024 2025 2026"
3. **WebFetch 至少 1 个 L1/L2 来源验证**

输出格式：

**核心问题**: {一句话定义}

**行业路线图**（3-5 条主要路线）：

| 路线 | 核心思路（一句话） | 主要代价（一句话） | 代表工作 | 成熟度 |
|------|------------------|------------------|---------|--------|
| {路线一} | ... | ... | ... | 成熟/发展中/早期 |

**本论文属于**: {路线名} — 做了什么独特选择: {一句话}

**各路线最新进展**（从搜索结果补充论文未覆盖的）：
- {路线}: {最新动态}（来源 URL）
```

### Agent 3: 历史脉络与前置文献对比

**description**: "对比{paper_title}前置文献"

**prompt**:

```
{全局约束}

你是学术研究分析专家。请梳理论文《{paper_title}》的历史脉络，逐一对比最直接的前置工作。

原文（Related Work / Introduction 重点关注）：{paper_content}
语言：{lang}

任务：
1. **从论文 References / Related Work 识别** 3-5 篇最直接的前置工作（被引用最多、被明确对比的）
2. **WebSearch 搜索每篇前置工作**（至少 2 次）：
   - "{前置论文标题} contribution method"
   - "{paper_title} vs {前置论文} comparison"
3. **WebFetch 至少 1 个来源验证**

输出格式（每篇前置工作一小段）：

**{前置工作1}**（{年份}）
- 做了什么：{一句话}
- 与本文的关键差异：{具体差异}（论文 Section X, References [N]）
- 本文在此基础上的推进：{一句话}

**{前置工作2}**（{年份}）
- ...

**演进链**: `[N1] 论文A (年份) → [N2] 论文B (年份) → 本文 (年份)`

**本文的核心价值/突出贡献**（基于以上对比得出）：
- 相比前置工作，本文真正推进了什么：{一句话}
- 贡献性质：{已有思路的新组合/重组 | 全新原理突破 | 工程规模推进 | 边界重新划分}

**其他支撑数据/证据**：
- {从搜索中发现的补充论据}（来源 URL）
```

### Agent 4: 团队背景与时机分析

**description**: "分析{paper_title}团队与时机"

**prompt**:

```
{全局约束}

## 专属约束
- 通讯作者/第一作者身份**必须从论文原文的作者标注确认**（通常用 * 或 † 或 corresponding author 标记），禁止从搜索结果的显眼程度推断
- **必须覆盖所有通讯作者**，不能只写搜索结果中最显眼的人
- 团队信息仅从作者主页/Google Scholar/DBLP/论文首页获取
- 无法验证的履历细节不写（不是标"待核实"，是不写）
- 禁止定性评价（"最具影响力""核心人物"），除非有官方奖项支撑
- 宁缺毋滥：信息不足时压缩为 2-4 句

你是学术情报分析专家。请分析论文《{paper_title}》的团队背景和时机。

作者：{authors}
**通讯作者（Phase 0 已从论文原文确认）**：{corresponding_authors}
机构：{institution}
摘要：{abstract}
原文（Introduction 部分）：{paper_content}
语言：{lang}

任务：
1. **识别关键角色**（直接使用 Phase 0 已确认的 {corresponding_authors}，不重复推断）：
   - 第一作者：从 {authors} 列表第一位确认
   - 通讯作者：直接使用 {corresponding_authors}
   - 末位作者：从 {authors} 列表末位确认
   - 列出每位关键角色的姓名和论文中标注的机构

2. **团队背景**（对每位通讯作者和第一作者分别搜索）：
   - **逐人搜索**：对每位通讯作者/第一作者各执行至少 1 次 WebSearch（如 "{作者名} {机构}" 或 "{作者名} Google Scholar"）
   - WebFetch 至少 2 个不同作者的主页/Scholar 页面
   - 每位关键角色：当前职位/头衔、研究方向、代表作（有 Scholar 页面的附引用量）
   - **机构领导层**：如机构为公司/实验室，搜索 "{机构名} CEO/director/leadership" 确认组织负责人，即使该人不是论文作者也应提及
   - 团队在该方向的前序工作（与本文的延续/突破关系）
   - **关键问题**：团队的哪些积累使他们能研究这个方向并得到这个解？

3. **Why Now — 时机分析**（WebSearch 至少 1 次）：
   - 问题背景：为什么这个问题现在变得尖锐？
   - 解决方案出现的时间必要性：哪些前置条件在近期成熟？
   - 识别 2-3 条正在汇合的技术/行业趋势

输出格式：

**关键角色**（从论文原文确认）:
- 第一作者：{姓名}（{机构}）
- 通讯作者：{姓名1}（{机构}）、{姓名2}（{机构}）...
- 末位作者：{姓名}（{机构}）

**Who & Where**:
- **{关键角色1姓名}**（{职位}）：{研究方向、代表作、引用量}（来源 URL）
- **{关键角色2姓名}**（{职位}）：{同上}（来源 URL）
- ...
- **机构背景**：{机构简介，含负责人/CEO（如适用）}
- 为何他们能做这个：{关键积累}

**Why Now**:
- 问题变尖锐的原因：{具体变化}（来源）
- 汇合趋势 1：{趋势}（来源）
- 汇合趋势 2：{趋势}（来源）
- 汇合趋势 3：{趋势}（来源）
```

## Phase 2: 综合分析与输出（主线程）

等待 5 个 Agent 全部返回后，执行以下步骤。

### Step 1: 信息整合与校验

逐项检查，任何一项不通过则回溯修正后再继续：

**事实核实 checklist**（逐项过）：
- [ ] **作者角色**：Agent 4 声称的通讯作者/第一作者是否与论文原文标注一致？不一致则以论文原文为准
- [ ] **关键人物覆盖**：所有通讯作者是否都有背景描述？是否遗漏了重要角色（如 CEO、末位作者）？遗漏则用 WebSearch 补充
- [ ] **机构归属**：Agent 4 声称的机构是否与论文首页一致？
- [ ] **关键数字**：Agent 1 提取的实验结果是否与论文 Table/Figure 原文吻合？
- [ ] **前置工作对比**：Agent 3 的差异描述是否与论文 Related Work 的原文陈述一致？

**一致性检查**：多个 Agent 对同一结论一致 = 高置信度
**矛盾处理**：不同来源评价不一致 → 在报告中标注争议
**来源审查**：L4 来源支撑的"事实"降级为"待验证"
**交叉关联**：
  - Agent 1（骨架）+ Agent 2（路线图）→ 本文在行业中的精确定位
  - Agent 3（历史）+ Agent 2（路线图）→ 演进脉络的完整性
  - Agent 5（场景）+ Agent 2（路线图）→ 不同路线的场景适配

### Step 2: 提炼决策判断

基于全部 Agent 输出，回答三个核心问题：
- **Whether**: 是否值得关注？（明确判断，不骑墙）
- **Why**: 为什么值得/不值得？（一句话核心理由）
- **How**: 如何使用这个信息？（具体行动建议）

### Step 3: 综合查漏补缺

审视完整报告，检查：
- 是否有关键信息缺失（如某条重要路线未覆盖）
- 引用链接是否完整
- 各部分之间逻辑是否连贯
- 决策判断是否有充分支撑

如发现缺口，使用 WebSearch/WebFetch 补充后再输出。
