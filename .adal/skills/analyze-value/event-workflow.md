# Event Workflow — Phase 1-3

本文件在 Phase 0B 定位事件成功后加载，包含并行采集、综合分析和报告输出的完整流程。

---

## 来源规则（全局适用）

### 来源分层

| 层级 | 来源类型 | 用途 |
|------|---------|------|
| **L1** | 官方声明、政策原文、当事方公告、权威统计机构数据 | 关键事实，必须标注出处 |
| **L2** | 权威媒体报道（路透社、Bloomberg、新华社等）、官方数据库 | 核实与补充 |
| **L3** | 行业分析师报告、专家评论、技术博客 | 解读视角，标注"外部解读" |
| **L4** | 自媒体、社交媒体、聚合站 | 不得支撑关键事实，仅作舆情参考 |

### 引用规则

- 关键断言**就地标注**来源：`（来源名, URL）`或`（官方数据, 发布日期）`
- 禁止段末堆链接
- 分析推断用"分析认为"标记
- 预测性判断用"预计/可能"标记，不得断言未发生的事

---

## Phase 1: 并行数据采集（5 个 Subagent）

**关键要求**: 5 个 Agent 必须放在**同一条消息**中发出，确保并行执行。

每个 Agent 使用 `subagent_type: "general-purpose"`。

**全局 Agent 约束**（放在每个 Agent prompt 开头）：

```
## 硬约束
1. 一手来源是核心事实源，关键断言必须标注具体来源和出处
2. L4 来源不得支撑关键事实
3. 分析推断用"分析认为"标记，预测用"预计/可能"标记
4. 区分已确认事实与未确认传闻
5. 字数上限 800 字，优先保留有一手源支撑的内容
```

### Agent 1: 事件本体提取（What & How）

**description**: "提取{event_title}核心要素"

**prompt**:

```
{全局约束}

你是事件分析专家。请从已采集的信息中提取事件核心要素。

事件：{event_title}
时间：{event_time}
状态：{event_status}
核心内容：{core_content}
一手信息源：{event_sources}
语言：{lang}

任务：
1. **核心问题**：用几个关键词概括事件涉及的核心问题/矛盾
2. **事件骨架**：提取事件的关键要素，压缩为 3-5 个要点，每点一句话描述，标注来源
3. **关键决策/转折点**：本事件中有哪些关键决策或转折，每个决策的影响
4. **当前进展**：已走到哪一步，下一步预期是什么
5. **WebSearch 补充**（至少 1 次）：搜索事件最新进展确认信息时效性

输出格式：
**核心问题**: {几个关键词}
**事件骨架**:
1. {要点}（来源）
2. ...
**关键决策/转折点**:
- {决策}: 影响 {xxx}（来源）
**当前进展**:
- 已完成：{xxx}
- 下一步预期：{xxx}（来源）
```

### Agent 2: 各方应对路线与格局

**description**: "调研{core_problem}各方应对路线"

**prompt**:

```
{全局约束}

你是行业策略分析专家。请调研事件「{event_title}」涉及的核心问题「{core_problem}」，各利益方的应对路线。

核心内容：{core_content}
关键主体：{key_actors}
一手信息源：{event_sources}
语言：{lang}

任务：
1. **从已有信息提取**：各利益方已公开的立场和应对策略
2. **WebSearch 补全**（至少 2 次搜索）：
   - "{core_problem} 应对策略 各方立场"
   - "{event_title} response strategy analysis"
3. **WebFetch 至少 1 个 L1/L2 来源验证**

输出格式：

**核心问题**: {一句话定义}

**各方应对路线**（3-5 个主要利益方/路线）：

| 利益方/路线 | 核心策略（一句话） | 主要代价（一句话） | 已采取行动 | 可行性 |
|------------|------------------|------------------|-----------|--------|
| {利益方一} | ... | ... | ... | 高/中/低 |

**路线间的博弈关系**：
- {利益方A} vs {利益方B}：{核心矛盾}（来源）

**最可能的走向**（分析认为）：
- {判断}，理由：{xx}
```

### Agent 4: 主体背景与时机分析（Who & Why Now）

**description**: "分析{event_title}主体与时机"

**prompt**:

```
{全局约束}

## 专属约束
- 主体信息仅从官方来源/权威媒体获取
- 无法验证的细节不写
- 禁止定性评价（"最具影响力"等），除非有客观依据支撑
- 宁缺毋滥：信息不足时压缩为要点

你是政经情报分析专家。请分析事件「{event_title}」的关键主体背景和时机。

关键主体：{key_actors}
核心内容：{core_content}
一手信息源：{event_sources}
语言：{lang}

任务：
1. **关键主体背景**（对每个关键主体分别搜索）：
   - **逐个搜索**：对每个关键主体各执行至少 1 次 WebSearch
   - WebFetch 至少 2 个不同主体的官方页面/权威报道
   - 每个主体：身份/角色、立场/动机、过往在此类事件中的行为模式
   - **关键问题**：这些主体的哪些特征使得事件走向现在这个方向？

2. **Why Now — 时机分析**（WebSearch 至少 1 次）：
   - 问题背景：为什么这个事件现在发生/浮出水面？
   - 触发条件：哪些前置条件在近期成熟？
   - 识别 2-3 条正在汇合的趋势（政策/经济/技术/社会）

输出格式：

**Who & Where**:
- **{主体1}**（{身份}）：{立场、动机、行为模式}（来源 URL）
- **{主体2}**（{身份}）：{同上}（来源 URL）
- ...
- 为什么这些主体推动了这个方向：{分析}

**Why Now**:
- 触发条件：{具体变化}（来源）
- 汇合趋势 1：{趋势}（来源）
- 汇合趋势 2：{趋势}（来源）
- 汇合趋势 3：{趋势}（来源）
```

## Phase 2: 综合分析与输出（主线程）

等待 5 个 Agent 全部返回后，执行以下步骤。

### Step 1: 信息整合与校验

逐项检查，任何一项不通过则回溯修正后再继续：

**事实核实 checklist**（逐项过）：
- [ ] **关键事实一致性**：多个 Agent 对同一事实的描述是否一致？不一致则以 L1/L2 来源为准
- [ ] **时间线准确性**：事件发生时间、关键节点是否与一手来源吻合？
- [ ] **主体信息准确性**：Agent 4 中的主体身份/角色是否与官方来源一致？
- [ ] **历史先例准确性**：Agent 3 的类比是否恰当？是否存在更合适的先例？
- [ ] **影响评估合理性**：Agent 5 的影响判断是否有充分证据？是否存在明显遗漏？

**一致性检查**：多个 Agent 对同一结论一致 = 高置信度
**矛盾处理**：不同来源评价不一致 → 在报告中标注争议
**来源审查**：L4 来源支撑的"事实"降级为"待验证"
**交叉关联**：
  - Agent 1（事件骨架）+ Agent 2（各方路线）→ 事件的核心博弈结构
  - Agent 3（历史先例）+ Agent 2（各方路线）→ 可能的走向判断
  - Agent 5（影响评估）+ Agent 4（时机分析）→ 影响的深度和持续性

### Step 2: 提炼决策判断

基于全部 Agent 输出，回答三个核心问题：
- **Whether**: 是否值得关注？（明确判断，不骑墙）
- **Why**: 为什么值得/不值得？（一句话核心理由）
- **How**: 如何使用这个信息？（具体行动建议）

### Step 3: 综合查漏补缺

审视完整报告，检查：
- 是否有关键信息缺失（如某个重要利益方未覆盖）
- 引用链接是否完整
- 各部分之间逻辑是否连贯
- 决策判断是否有充分支撑
- 事实与预测是否清晰区分

如发现缺口，使用 WebSearch/WebFetch 补充后再输出。
