### Step 1: LinkedIn Post

Copy and paste this:

```
I read all the essays from Paul Graham, Sam Altman, Michael Seibel, and studied how Patrick Collison and Brian Chesky built Stripe and Airbnb.

Then I created a Claude Skill that synthesizes everything into a decision framework for development.

The central question before any technical decision:

"Will this help the next customer pay?"

---

5 principles I learned from YC and Silicon Valley:

1. Michael Seibel: "If you walk away with one thing, launch something bad quickly"
   → Your first version MUST be embarrassing

2. Patrick Collison built Stripe with Ruby + MongoDB
   → Validation > architectural purity. Ugly code that works > elegant code that doesn't exist

3. Brian Chesky at Airbnb: do things manually until it hurts
   → Don't automate what doesn't hurt

4. Paul Graham: "Default alive or default dead?"
   → If you don't reach profitability before running out of money, nothing else matters

5. Sam Altman: "It's better to make a decision and be wrong than to equivocate"
   → Indecision kills more startups than bad decisions

---

The skill includes:
• Decision framework (4 key questions)
• P0/P1/P2/NEVER prioritization system
• When to accept vs pay vs ignore technical debt
• Quick decisions: tests, refactoring, CI/CD

Open source on GitHub (link in comments).

---

Which of these principles contradicts what you learned in university the most?
```
